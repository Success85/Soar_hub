# API & backend reference

SOAR Hub is a server-rendered app: almost all mutations are **Server Actions** (typed, origin-checked POSTs
generated by Next.js), so there is no public REST API for third parties. All return
`ActionResult = { ok: true, data?, message? } | { ok: false, error, fieldErrors? }` and never leak stack traces.

## HTTP route handlers

| Method & path | Auth | Purpose |
|---|---|---|
| `GET /api/health` | none | Liveness + DB check → `{status, db, latencyMs}` (503 if DB down) |
| `GET /api/files/:versionId[?inline=1]` | session; owner / assigned reviewer / permitted admin | Authorises, logs non-owner access, 303 → 120-s signed URL |
| `GET /api/dev-storage?key&exp&fn&ct&inl&sig` | HMAC signature | Development-only local file serving (404 in production) |
| `GET|POST /api/cron/:group` | `Authorization: Bearer $CRON_SECRET` | `frequent`, `hourly`, `daily`, or a single job name (see below) |
| `POST /api/webhooks/email` | Svix signature (Resend) or `?secret=` (SendGrid) | Delivery/bounce receipts → notification status |
| `POST /api/webhooks/sms` | `?secret=` | Africa's Talking delivery reports |
| `GET /api/admin/scholarship-files/:id` | `scholarships.manage` | Internal scholarship evidence file → signed URL |
| `GET /api/admin/export/:kind` | `exports.basic` (+`exports.sensitive` for `?sensitive=1`) | CSV: `applicants` (same filters as Admin → Applicants), `analytics` |

Jobs: `dispatch-notifications`, `ai-critiques`, `milestone-reminders`, `overdue-reminders`, `referee-reminders`,
`referee-expiry`, `scholarship-expiry`, `embeddings-backfill`, `analytics-aggregate`, `cleanup`.
Groups: frequent = dispatch + AI; hourly = referee expiry, scholarship expiry, embeddings; daily = reminders,
analytics, cleanup, dispatch.

## Services (src/lib/services) — the only layer that touches the database

`auth`, `profile`, `scholarships`, `eligibility`, `applications`, `planner`, `documents`, `essays` (incl. AI
pipeline), `answer-bank`, `referees`, `notifications`, `admin` (stats, applicants, reviewers, users, roles,
audit search), `content`, `analytics`, `privacy`, `dashboard`, `jobs`, `access`, `audit`, `rate-limit`, `settings`.

Pagination: list services accept `page` (25–50 per page) and return `{rows, total, page}`. Search/filter/sort
parameters are documented on each function signature.
